# 펌웨어 버전 관리

| --- | --- | --- | ---: | --- |

현재 버전은 사용자가 장치에 적용했던 최소 펌웨어입니다. 구형 파일 64개 정리, Wi-Fi·밝기·로그인 비밀번호 보존, 밝기 즉시 적용·자동 저장, 비밀번호 변경, 읽기 전용 파일 목록, 웹 업데이트와 복구 기능을 포함합니다. 자세한 실기 기록은 [장치 상태](../docs/device-state.md)에 있습니다.

사용자가 첨부한 파일을 그대로 보관했으며, SHA-256과 파일 크기가 이전 배포 기록에 일치합니다. ESP8266 이미지 헤더와 기록된 이미지 크기도 확인했습니다. 이번 등록 과정에서 재빌드·장치 설치·실기 테스트는 하지 않았습니다. 커스텀 소스가 아직 없으므로 이 버전은 바이너리 보관 단계입니다.

## 파일 구성과 무결성 확인

버전별 디렉터리에는 원본 `.bin`, [manifest.json](1.3.2-minimal-clean64/manifest.json), [SHA256SUMS](1.3.2-minimal-clean64/SHA256SUMS)를 함께 둡니다. 다운로드 후 해당 디렉터리에서 다음 명령으로 확인할 수 있습니다.

```sh
sha256sum -c SHA256SUMS
```

Windows PowerShell에서는 다음 명령의 결과를 `SHA256SUMS`와 비교합니다.

```powershell
Get-FileHash -Algorithm SHA256 .\SDP-Minimal-Clean64.bin
```

장치의 웹 업데이트에는 `.bin` 파일을 선택합니다. `SDP`로 시작하는 원래 파일명은 유지합니다. Git 태그는 바이너리와 함께 해당 시점의 문서·메타데이터를 고정합니다.

## 다음 버전 등록

1. 펌웨어 버전마다 새 디렉터리를 만들고, 기존 버전의 바이너리와 태그는 덮어쓰지 않습니다.
2. `.bin`의 실제 크기와 SHA-256을 계산해 `manifest.json`, `SHA256SUMS`를 함께 저장합니다.
3. 변경 내용과 PC 검사·실기 확인 범위를 기록하고 위 버전 목록을 갱신합니다.
4. 원본 소스를 확보한 뒤에는 소스·빌드 설정도 함께 커밋합니다.
5. 해당 커밋에 `v<펌웨어 버전>` 형식의 주석 있는 Git 태그를 만들고 커밋과 태그를 push합니다.

펌웨어 업로드가 성공했던 과거 버전으로 돌아가도 파일시스템이나 설정 데이터까지 자동으로 이전 상태로 복원되지는 않습니다.
