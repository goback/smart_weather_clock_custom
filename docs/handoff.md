기존 작업은 Windows PC에서 수행했습니다. 현재 클라우드 작업 공간과 GitHub 저장소에는 해당 소스·바이너리가 없었습니다. 아래는 기존 채팅의 명령 출력으로 확인한 **당시 위치**이며, 현재 파일 존재 여부는 재확인하지 않았습니다.

| 대상 | 당시 위치 |
| --- | --- |
| 마지막 펌웨어 프로젝트 | `C:\dev\smart_weather_clock_custom\work\sdpro-minimal-clean64` |
| 빌드 결과 | 위 프로젝트의 `.pio\build\esp12e\firmware.bin` |
| 사용자에게 제공한 파일 | `%USERPROFILE%\Documents\Codex\2026-11-08\referenced-chatgpt-conversation-this-is-an\outputs\SDP-Minimal-Clean64.bin` |
| 기반 프로젝트 사본 | `%USERPROFILE%\Documents\Codex\2026-11-08\referenced-chatgpt-conversation-this-is-an\work\smartclock-oss-1.3.2` |

개발을 재개하려면 마지막 프로젝트의 `src/`, `include/`, `web/`, `scripts/`, `tests/`, `platformio.ini`, `LICENSE`를 원본 그대로 가져옵니다. `.pio` 캐시·툴체인 전체나 실제 장치 설정 파일을 가져올 필요는 없습니다. 테스트용 별도 디렉터리 `work/sdpro-minimal-clean64-check`에도 당시 검증 코드가 있었습니다.

채팅에 있는 변경 조각만으로 전체 펌웨어를 복원하거나, 최신 upstream 소스로 원본을 대체한 뒤 같은 빌드라고 취급하지 않습니다. 우선 위 원본과 아래 바이너리 지문을 확보하는 것이 다음 작업입니다.

## 빌드와 업데이트 제약

기존 최종 빌드의 도구·라이브러리 기록:

- PlatformIO 환경 `esp12e`, 플랫폼 `espressif8266 @ 4.2.1`.
- Arduino ESP8266 코어 3.1.2, TFT_eSPI 2.5.43, ArduinoJson 7.4.3.
- 기존 플래시 링커 레이아웃 `eagle.flash.4m3m.ld` 유지.
- 웹 OTA용 이미지 상한 `0x7E000` = 516,096바이트 (504 KiB).
- 관리 페이지 HTML을 gzip으로 펌웨어에 내장. 기존 LittleFS의 웹 파일에 의존하지 않음.

프로젝트 원본 확보 후 기존 스크립트와 설정을 확인하고 `pio run -e esp12e`로 빌드합니다. 당시 릴리스 빌드에는 `SMARTCLOCK_RELEASE=1`을 사용했습니다. 디스플레이 핀·드라이버·회전·백라이트 극성과 이미지 검증 코드를 유지합니다.

펌웨어 업데이트는 관리 페이지의 웹 업데이트에서 호환 `.bin`으로 수행합니다. 이 방식은 실행 펌웨어를 바꾸고 파일시스템을 별도로 덮어쓰지 않습니다. 파일명을 `SDP`로 시작하게 하는 조건과 실제 이미지 호환성 검사는 별개입니다. 제조사 원본으로 복귀하는 경로는 UART가 필요하다고 기존 기반 문서에 안내돼 있습니다.

장치가 설정 AP를 띄우는 경우 기존 네트워크 이름은 `Smart Weather Clock`, 주소는 `http://192.168.4.1/`입니다. 비밀번호는 장치 화면에서 확인합니다. 앱 안에 설정용 AP와 복구 기능이 있어도 전체 플래시 백업을 대신하지는 않습니다.

## 기존 검증 범위

기존 최종 빌드 출력에서 확인한 PC 검사:

- 64개 목록의 고유성·크기 합계, 설정 확인 후 정리, 크기가 바뀐 파일·추가 파일 보존, 재부팅 후 재시도·완료 표시.
- 로그인·현재 비밀번호 확인·잠금·새 비밀번호 검증·저장 실패와 성공 처리.
- 관리 페이지 비밀번호 폼·확인·복구 상태·밝기 처리.
- 짧은 부팅 3회 복구 카운터와 EEPROM 영역 보존.
- OTA 이미지의 잘림·손상·초과 크기·파일시스템 이미지 거부, 업로드 중단·재시도, 업데이트 실패 처리.
- 최종 이미지의 4 MiB 헤더·파일 크기·기존 파일시스템 배치·내장 웹 페이지.

실기에서는 최초 커스텀 펌웨어의 부팅·화면 출력에 대한 사용자 확인과, 최종 Clean64 적용 후 정리 결과·남은 파일·용량 조회까지 기록돼 있습니다. 모든 복구·오류 경로를 실기에서 시험한 것은 아닙니다.

## 다음 기능

사용자의 목표는 장치를 원하는 화면과 동작으로 자유롭게 커스터마이징하는 것입니다. 최소 펌웨어와 파일 정리는 끝났고, 구체적인 다음 기능은 아직 선택하지 않았습니다.

기존 채팅의 마지막 제안은 관리 페이지에서 제목·큰 숫자·한 줄 메시지·색상을 편집해 장치에 표시하는 기능입니다. 이후 장치 자체 타이머·디데이나 서버에서 받은 데이터 표시로 확장할 수 있습니다. 이 편집 화면, 타이머, 외부 데이터 API는 현재 구현된 기능이 아닙니다.
